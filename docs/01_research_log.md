# 임산부 혜택 통합 서비스 - 리서치 로그

## 프로젝트 배경

임산부 관련 정부 혜택 정보가 중앙정부/광역시도/기초자치단체에 흩어져 있어서
일반 사용자가 자신에게 해당하는 혜택을 찾기 어려운 문제를 해결하기 위한 프로젝트.

**목표**: 사용자의 지역 + 임신 여정 단계(임신준비→임신→출산→양육)에 맞는 혜택을 한 곳에서 보여주기

## Phase 1: 공공 API 데이터 수집 (완료)

### API 소스 선정

| API | URL | 상태 |
|-----|-----|------|
| 보조금24 (행정안전부) | `https://api.odcloud.kr/api/gov24/v3/serviceList` | **채택** |
| 복지로 중앙부처 | `https://apis.data.go.kr/B554287/NationalWelfareInformationsV001` | 보조금24에 포함 |
| 복지로 지자체 | `https://apis.data.go.kr/B554287/LocalGovernmentWelfareInformations` | 403 (별도 승인 필요) |

**결론**: 보조금24 단일 API로 90%+ 커버 가능

### API 인증 삽질 기록

- URL-encoded 키(`%2F` 등)를 requests 라이브러리에 넣으면 **이중 인코딩** 발생 → 401 에러
- **해결**: decoded 키를 .env에 별도 저장하여 사용
- 일일 호출 제한: 1,000회 (100회는 오해였음)
- perPage=500으로 설정하면 22회 호출로 전체 수집 가능

### 데이터 수집 결과

**3단계 수집 전략**:

1. **1차 (서비스분야 필터)**: `cond[서비스분야::LIKE]=임신` → 898건
2. **2차 (키워드 확장)**: 63개 키워드로 추가 검색 → +819건 신규
3. **노이즈 제거**: 24개 패턴 (가축, 참전유공자, 문화유산 등) → -일부 제거

**최종 결과**: 1,717건 (2.7MB JSON)

### 카테고리 체계

```
임신: 1,021건 (임신, 임산부, 난임, 태아, 산전, 엽산 등)
출산: 1,055건 (출산, 분만, 산모, 신생아, 출생 등)
양육:   970건 (양육, 육아, 보육, 어린이집, 영유아 등)
기타:    일부 (복수 태깅 가능)
```

### 21개 데이터 필드

서비스ID, 서비스명, 서비스목적요약, 서비스분야, 지원내용, 지원대상, 지원유형,
선정기준, 신청방법, 신청기한, 접수기관, 전화문의, 소관기관명, 소관기관유형,
소관기관코드, 부서명, 사용자구분, 상세조회URL, 조회수, 등록일시, 수정일시

### 파일 위치

### 중요 발견: 시청 ≠ 보건소

**시청과 보건소가 다른 CMS를 사용하는 경우가 많다!**

| 도시 | 시청 CMS | 보건소 CMS |
|------|---------|-----------|
| 수원시 | JSP 경로형 (.jsp) | ASP (.asp?page_code=) |
| 전주시 | 독자 CMS (.9is) | E-CMS (menuCd=DOM_) |
| 대전시 | 홍익인간 (.do?menuSeq=) | 동일 |
| 성남시 | 별도 시스템 | contents.do (패턴A) |

→ 크롤러를 **시청용 + 보건소용 2벌** 필요할 수 있음

## Phase 2.5: 전국 보건소 URL 자동 탐색 (완료)

### 왜 자동 탐색?

수동으로 각 지자체 보건소 URL을 하나씩 검색하는 것은 비효율적.
Python 스크립트로 전국 140개 지자체 보건소를 자동 탐색하여 URL 레지스트리 구축.

### 자동 탐색 전략

```
1. 전국 140개 지자체 보건소 도메인 목록 구축
   - 서울 25구, 부산 16구, 대구 8구, 인천 10구, 광주 5구
   - 울산 5구, 대전, 세종, 경기도 31시
   - 충청/전라/경상/강원/제주 주요 시

2. 각 보건소별로 다단계 URL 접근
   - 1차: https://{domain}{health_path}/main.do
   - 2차: https://{domain}{health_path}/index.do
   - 3차: https://{domain}{health_path}
   - 4차: https://{domain} (메인사이트)

3. HTML 파싱으로 임산부/모자보건 메뉴 자동 발견
   - 키워드: 모자보건, 임산부, 임신, 출산, 산모, 신생아 등
   - 2depth 탐색: 보건사업/사업안내 메뉴 → 하위 메뉴에서 재검색

4. URL 패턴 자동 분류 (6가지 패턴)
```

## Phase 2.8: Playwright Headless 스캔 (완료)

### 배경

Phase 2.7 후 26개 "accessible" 사이트 중 대부분이 SPA/JS 렌더링 사이트.
BeautifulSoup은 raw HTML만 파싱하므로 JS 렌더링 콘텐츠를 읽을 수 없음.
기존 `/crawl` 스킬 (web-crawler-v2.py)의 Playwright 패턴을 활용하여 배치 스캔.

### 구현

`scripts/discover_health_urls_playwright.py` 작성:
- `async_playwright` + `chromium.launch(headless=True)`
- `wait_until="networkidle"` (+ domcontentloaded 폴백)
- `page.evaluate`로 JS 렌더링 완료 후 `<a>` 태그 전체 추출
- 기존 MENU_KEYWORDS / MID_MENU_KEYWORDS 키워드 매칭 로직 재사용
- depth 1~3 탐색, 결과를 기존 scan JSON / url_registry에 머지

### 결과 (2026-02-12)

26개 accessible 중 에러 URL 7개 제외 → 19개 스캔:

| 결과 | 수 | 사이트 |
|------|-----|--------|
| **신규 발견** | 7개 | 부천시, 서울 성북구, 성남시, 수원시, 안산시, 울산 남구, 포천시 |

## Phase 3: 보건소 콘텐츠 크롤링 (완료)

Phase 2에서 발견한 104개 보건소 URL 중 url_registry.json에 등록된 42개 사이트에서
실제 임산부 프로그램 콘텐츠를 추출하여 보조금24 API 데이터와 비교.

### 크롤링 전략 (v3)

- **기술**: requests + BeautifulSoup (Playwright 없이 빠르게)
- **병렬**: ThreadPoolExecutor 5개 스레드
- **추출 전략**: 5단계 파싱
  1. 테이블 구조 파싱 (가장 정확)
  2. dl/dt/dd 정의 목록
  3. h2/h3/h4 + 형제 요소
  4. li 리스트 항목
  5. 본문 단락 fallback
- **노이즈 필터링**: 전화번호, URL, 행정 안내문 등 제외
- **소요 시간**: ~2분 (v2 Playwright 대비 10배+ 빠름)
